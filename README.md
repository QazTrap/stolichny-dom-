# STOLDOM.SITE — модуль проверки контрагентов

Первый модуль платформы: поиск по БИН через API «Сведения по контрагентам (Открытые данные)» КГД РК.

## Что уже реализовано в этой ветке

- интерфейс на русском языке;
- ввод и проверка 12-значного БИН;
- серверный POST-запрос к `/services/isnaportal/public/get-sur-data`;
- передача `X-Portal-Token` только с backend;
- отображение регистрационных, налоговых и дополнительных сведений;
- вывод налоговой задолженности и статистики по годам;
- отдельное отображение «Нет данных» без трактовки этого значения как отсутствия нарушения;
- QR-код, который открывает повторную проверку по тому же БИН;
- печатная форма A4 и диалог сохранения в PDF;
- обработка ошибок КГД 400, 401, 404, 500;
- базовые ограничения частоты запросов и CORS.

## Запуск backend локально

Требуется Node.js 20 или новее.

```bash
npm install
cp .env.example .env
# заполнить KGD_API_TOKEN в .env
npm start
```

Проверка состояния: `GET /api/health`.

Проверка контрагента: `POST /api/counterparty` с JSON `{"xin":"071140005693"}`.

QR: `GET /api/counterparty/071140005693/qr`.

## Развёртывание

### Backend на Railway

1. Подключить репозиторий `QazTrap/stolichny-dom-` и выбрать ветку `feature/stoldom-counterparty-check`.
2. Убедиться, что команда запуска — `npm start`.
3. В Railway Variables добавить значения из `.env.example`.
4. Полученный от администратора КГД токен поместить в `KGD_API_TOKEN`. Не отправлять токен в чат, GitHub или frontend.
5. Указать публичный домен backend и добавить домен сайта в `CORS_ORIGINS`.

### Frontend на статическом хостинге

В `index.html` у meta-тега `name="stoldom-api-base"` указать публичный URL backend, например:

```html
<meta name="stoldom-api-base" content="https://ВАШ-БЭКЕНД.up.railway.app">
```

До появления реального Railway-домена значение оставлено пустым. Поэтому frontend пока не подключён к работающему серверу.

## Переменные окружения

- `KGD_PORTAL_HOST` — базовый адрес портала КГД; по умолчанию `https://portal.kgd.gov.kz`.
- `KGD_API_TOKEN` — секретный `X-Portal-Token`, предоставленный администратором КГД.
- `PUBLIC_APP_URL` — публичный адрес frontend, который кодируется в QR.
- `CORS_ORIGINS` — разрешённые frontend-домены через запятую.

## Ограничения текущей версии

- Для реального запроса нужен действующий токен КГД и разрешённый доступ к сервису.
- Успешный ответ API ещё не проверен без токена.
- PDF создаётся через системный диалог печати браузера («Сохранить как PDF»).
- QR повторно запрашивает актуальные данные по БИН; он не является архивной копией старой справки.
- Адрес регистрации не включён в пример ответа API. Для него понадобится отдельный подтверждённый источник.
- Совместимый файл импорта в 1С пока не формируется: формат нужно проверить на целевой конфигурации 1С.
- История проверок и массовая загрузка Excel будут отдельными этапами.

## Безопасность

Токен КГД хранится только в серверной переменной окружения. Не добавлять его в HTML, JavaScript браузера, публичный репозиторий или логи.
