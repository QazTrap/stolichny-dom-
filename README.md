# STOLDOM.SITE — рабочее место бухгалтера

Браузерный инструмент для предварительной обработки банковских выписок, сверки итогов и подготовки контрольного Excel перед загрузкой в **1С:Бухгалтерию для Казахстана**. Светлый интерфейс, без демонстрационных данных.

## Что работает

- Загрузка банковских выписок в форматах XLSX, XLS, CSV и TXT; обработка нескольких листов Excel, локально в браузере.
- Распознавание даты, направления, суммы, контрагента, назначения платежа, номера документа и БИН/ИИН, если в файле присутствуют соответствующие колонки.
- Определение входящих/исходящих по колонкам «Дебет» и «Кредит», по явному признаку направления или по отрицательному знаку суммы. Если направление невозможно установить, операция **требует проверки**, а не получает выдуманный тип документа.
- Сокращение организационно-правовых форм (ТОО, ИП и др.) только при отображении/подготовке.
- Предложение статьи ДДС по назначению платежа (поставщики, покупатели, налоги, ОПВ/ВОСМС, комиссии, аренда, зарплата, займы, возвраты). Бухгалтер может выбрать другую статью или вписать свою.
- Редактирование направления, типа документа, статьи ДДС, счетов 1С, контрагента и назначения платежа.
- Статусы «Проверить», «Документ определён», «Готово» с проверкой необходимых полей. Отсутствующие счета бухгалтерского учёта автоматически не выдумываются.
- Поиск, фильтры, количество и **суммы поступлений/списаний/разницы** по текущему фильтру.
- Сверка итогов за выбранную дату, отдельно по входящим, исходящим или всем операциям.
- Выявление возможных дублей внутри загруженной выписки; они сохраняются в списке, но требуют отдельного подтверждения.
- Просмотр незаполненных реквизитов перед экспортом.
- **Рабочая выгрузка XLSX**, в которой есть вкладки «Все операции», «Готовые», «На проверку», «Контроль».
- Автосохранение черновика **только в sessionStorage текущей вкладки** и экспорт/импорт черновика JSON для сохранения между сессиями.
- Для безопасности используется SheetJS CE 0.20.3, установленная из официального источника, с закреплённой версией библиотеки из официального CDN SheetJS; сторонние скрипты запрещены CSP.

## Важное ограничение для 1С

**Выгрузка XLSX — это контрольная таблица для подготовки данных, а НЕ файл прямого обмена с 1С.** Стандартная загрузка банковских выписок в 1С может ожидать формат клиент-банка \`1CClientBankExchange\` (\`kl_to_1c.txt\`) или иной формат конкретной обработки/конфигурации. Параметры 1С и сопоставление справочников (контрагенты, счета, статьи ДДС) необходимо проверить на тестовой базе. ПКО/РКО и платёжные поручения доступны для выбора, но их корректное создание в 1С этим сайтом **пока не подтверждено**. Сайт **не проводит** операции в 1С.

## Запуск

Требуется Node.js >=20.

\`\`\`bash
npm install
npm test
npm start
\`\`\`

Откройте http://localhost:3000. Проверка backend: http://localhost:3000/api/health.

**Важно:** зависимость \`xlsx\` берётся по прямому HTTPS-адресу официального CDN SheetJS, а не из устаревшего реестра npm. Развёртывание должно иметь доступ к \`https://cdn.sheetjs.com\` на этапе \`npm install\`. На GitHub Pages библиотека загружается из официального CDN SheetJS версии 0.20.3. Данные самой выписки не передаются на CDN, но для первой загрузки библиотеки нужен интернет.

## Архитектура

- \`server.js\` — Express, Helmet/CSP, статические скрипты и \`/api/health\`; **выписки на сервер не загружаются**.
- \`workspace-core.js\` — чистые правила импорта, дат, направлений, ДДС, проверки дублей, статусов и контрольных сумм.
- \`app.js\` — управление интерфейсом, локальные черновики и экспорт XLSX.
- \`index.html\` — интерфейс в светлой теме.
- \`tests/workspace-core.test.js\` — проверки на Node.js; workflow запускает тесты при push.

## Работа с выпиской

1. Загрузите файл банковской выписки (максимум 20 МБ, до 20 000 операций).
2. Сверьте дату, направления, итоги поступлений и списаний с исходным банком.
3. Проверьте операции со статусом «Проверить». Укажите **реальные** счета бухгалтерского учёта, ДДС и тип документа; подтвердите выявленные дубли только после сверки.
4. Нажмите «Предварительный просмотр», затем «Скачать Excel для подготовки 1С».
5. После согласования формата обмена и теста в 1С переносите данные в рабочую базу.

## Безопасность данных

Банковские реквизиты и назначения платежей могут быть конфиденциальными. Не используйте общедоступный/чужой компьютер. Черновик JSON и Excel скачиваются на устройство и требуют безопасного хранения. Автосохранение хранит данные в рамках вкладки и не синхронизирует их с сервером. Для удаления данных вкладки нажмите «Очистить сессию» и удалите скачанные файлы самостоятельно.

## Не реализовано

- Прямой обмен или проведение в 1С, выгрузка \`1CClientBankExchange\` с гарантией совместимости.
- Синхронизация реальных статей ДДС и контрагентов из справочников конкретной базы 1С.
- Проверка дублей относительно **уже существующих** операций в базе 1С.
- Личный кабинет, серверное хранение и история между устройствами.
- API КГД: ранее запланированный модуль проверки контрагентов не включён в эту версию.
