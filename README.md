# STOLDOM.SITE — модуль проверки контрагентов

Первый рабочий модуль платформы: поиск по БИН через API «Сведения по контрагентам (Открытые данные)» КГД РК.

## Что реализовано

- русскоязычный интерфейс проверки по 12-значному БИН;
- серверный POST-запрос к `/services/isnaportal/public/get-sur-data`;
- передача `X-Portal-Token` только с backend;
- регистрационные сведения, ОКЭД, налоговый режим и НДС;
- задолженность, признаки и статистика по годам;
- отдельное отображение «Нет данных» без трактовки этого значения как отсутствия нарушения;
- QR-код для повторной проверки по тому же БИН;
- печатная форма A4 и сохранение через диалог браузера в PDF;
- обработка ошибок КГД 400, 401, 404 и 500;
- ограничение частоты запросов и защитные HTTP-заголовки Helmet.

## Архитектура

Один Node.js-сервис обслуживает и сайт, и API:
- `GET /` — интерфейс STOLDOM.SITE из `index.html`;
- `GET /api/health` — состояние backend и признак наличия токена;
- `POST /api/counterparty` — запрос сведений в КГД;
- `GET /api/counterparty/:xin/qr` — QR-код повторной проверки.

Frontend обращается к API по тому же домену. Отдельный статический хостинг для этой версии не требуется.

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm install
cp .env.example .env
# заполнить KGD_API_TOKEN в .env
npm start
```

Откройте `http://localhost:3000`.

Проверка состояния: `GET /api/health`.

Проверка контрагента: `POST /api/counterparty` с JSON `{"xin":"071140005693"}`.

## Развёртывание на Railway

1. Создать отдельный проект/сервис для STOLDOM.SITE. Не подключать эту ветку к сервисам ASIQPAI или другим действующим проектам.
2. Подключить репозиторий `QazTrap/stolichny-dom-` и выбрать ветку `feature/stoldom-counterparty-check`.
3. Build command: `npm install` (можно оставить автоматическое определение Railway).
4. Start command: `npm start`.
5. Добавить переменные окружения из `.env.example`.
6. Указать публичный адрес сайта в `PUBLIC_APP_URL` (он используется для QR-кодов).
7. После получения токена от КГД добавить его в `KGD_API_TOKEN` через Railway Variables. Не отправлять токен в чат, GitHub или frontend.
8. После деплоя проверить `/api/health`, главную страницу, QR и запрос к КГД.

## Переменные окружения

- `KGD_PORTAL_HOST` — базовый адрес портала КГД; по умолчанию `https://portal.kgd.gov.kz`.
- `KGD_API_TOKEN` — секретный `X-Portal-Token`, предоставленный администратором КГД.
- `PUBLIC_APP_URL` — публичный адрес сайта, который кодируется в QR.

## Что пока не подключено или не проверено

- Реальный запрос к КГД не проверен: токен `X-Portal-Token` ещё не получен.
- Успешный ответ API не проверен на действующих данных.
- PDF создаётся через системный диалог печати браузера («Сохранить как PDF»).
- QR повторно запрашивает актуальные данные по БИН; он не является архивной копией старой справки.
- Адрес регистрации отсутствует в предоставленном примере ответа API. Для него понадобится отдельный подтверждённый источник.
- Значения `taxDebt1..4` не расшифрованы в документации; интерфейс не присваивает им выдуманные названия.
- Импорт в 1С, история проверок и массовая загрузка Excel пока не реализованы.

## Безопасность

Токен КГД хранится только в серверной переменной окружения. Не добавлять его в HTML, JavaScript браузера, публичный репозиторий или логи.

## Сверка ЭСФ с 1С

Откройте `/reconciliation` и загрузите две выгрузки за одинаковый период:
- реестр ЭСФ из ИС ЭСФ;
- соответствующий реестр/таблицу из 1С.

Поддерживаются XLSX, XLS, XLSM и CSV (до 15 МБ на файл). Для первой версии используется первый лист. После загрузки проверьте автоматическое сопоставление колонок: номер документа и БИН обязательны; дата, сумма и НДС используются для дополнительной проверки.

Документы сопоставляются по паре **БИН + номер документа**. Результаты: совпадение, расхождение даты/суммы/НДС, документ отсутствует в 1С или отсутствует в выгрузке ЭСФ. Отчёт можно скачать в CSV или распечатать/сохранить в PDF.

### API сверки

- `POST /api/reconciliation/preview` — принять два файла и вернуть названия колонок, число строк и примеры.
- `POST /api/reconciliation/compare` — выполнить сверку с JSON-сопоставлением колонок в поле `mapping`.

Файлы обрабатываются в памяти сервера, не сохраняются в БД и не отправляются сторонним сервисам. Модуль не изменяет документы и проводки в 1С. Перед использованием на рабочих данных проверьте результат на копиях выгрузок: форматы отчётов ИС ЭСФ и 1С могут отличаться.
