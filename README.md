# STOLDOM.SITE

**Рабочее место бухгалтера для обработки банковских выписок и подготовки операций к переносу в 1С.**

**Версия:** 1.1.0 · **Язык интерфейса:** русский · **Интерфейс:** светлый, без демонстрационных операций.

STOLDOM.SITE помогает загрузить банковскую выписку, проверить операции, сопоставить бухгалтерские реквизиты и скачать контрольную Excel-таблицу. Основная обработка выполняется в браузере; исходная выписка не отправляется в серверное API STOLDOM.SITE.

> **Важно:** сейчас формируется Excel **для подготовки и сверки**, но не проверенный файл прямого обмена с 1С. Автоматическое создание и проведение документов в 1С пока не реализовано.

## Возможности

| Раздел | Что делает |
| --- | --- |
| Импорт выписки | Читает XLSX, XLS, CSV, TXT, включая несколько листов Excel |
| Распознавание | Извлекает дату документа (не дату формирования выписки), сумму, направление, контрагента, назначение, КНП, БИН/ИИН и номер документа, когда они есть в исходном файле |
| Направление | Определяет поступления и списания по дебету/кредиту, признаку направления или знаку суммы; неопределённые операции оставляет на проверку |
| Статьи ДДС | Учитывает направление платежа, назначение и КНП (например, 841 — банковские комиссии в подтверждённом контексте); различает налоги, услуги, алименты и исполнительные документы. Показывает причину предложения и позволяет выбрать статью вручную |
| Редактирование | Позволяет менять дату, сумму, направление, тип документа 1С, ДДС, счета дебета/кредита, контрагента и назначение |
| Типы документов | Платёжные поручения, **платёжный ордер (списание денежных средств)**, ПКО, РКО и поступление/списание с расчётного счёта (выбор для подготовки, не создание в 1С) |
| Контроль | Считает поступления, списания, разницу и количество с учётом фильтров; позволяет сверять конкретную дату |
| Проверка | Показывает незаполненные реквизиты, статусы и возможные дубли внутри загруженного набора операций |
| Черновики | Автосохранение в текущей вкладке; скачивание и восстановление черновика в JSON; кнопка «Пересчитать ДДС» обновляет только автоматические предложения, не перезаписывая ручные |
| Экспорт | Excel с листами **Все операции**, **Готовые**, **На проверку**, **Контроль** |

Поддерживаются сокращения «Товарищество с ограниченной ответственностью» → «ТОО», «Индивидуальный предприниматель» → «ИП» и некоторых других организационно-правовых форм.

**Ограничения:** исходный файл не должен превышать 20 МБ, импорт — 20 000 операций. На экране одновременно отображаются первые 400 операций по выбранному фильтру, но расчёт итогов и экспорт работают со всем загруженным набором.

## Порядок работы

1. Нажмите **«Загрузить выписку»** и выберите файл.
2. Сверьте число операций, даты, суммы поступлений и списаний с исходной выпиской.
3. Используйте фильтры **«Входящие»**, **«Исходящие»**, статусы, поиск и **«Проверить сумму за дату»**. При необходимости нажмите **«↻ Пересчитать ДДС»**: значения, сохранённые бухгалтером вручную, не изменятся.
4. Откройте строки со статусом **«Проверить»** и укажите корректные счета бухгалтерского учёта, тип документа 1С и статью ДДС. Автоматические предложения ДДС обязательно проверяйте.
5. При обнаружении похожих строк проверьте их по банку. Система **не удаляет дубли автоматически**. Если файл был импортирован до обновления правил, загрузите исходную выписку заново, чтобы прочитать КНП и правильную дату документа.
6. Нажмите **«Предварительный просмотр»**, затем **«Скачать Excel для подготовки 1С»**.
7. Проверьте сформированный Excel перед дальнейшей ручной обработкой или настройкой обмена в тестовой базе 1С.

**Статусы:** «Документ определён» означает, что направление и допустимый тип документа распознаны, но другие реквизиты могут быть не заполнены. «Готово» означает, что обязательные поля формы заполнены и базовые проверки пройдены; это **не** подтверждает пригодность операции для проведения в конкретной базе 1С.

При выборе ПКО/РКО проверяется использование кассового счёта **1010** (дебет для ПКО и кредит для РКО). Автоматическое сопоставление счетов и справочников с конфигурацией 1С отсутствует.

## Банковская комиссия и тип документа 1С

При распознавании банковской комиссии программа автоматически предлагает:
- **Направление:** «Исходящие».
- **Статья ДДС:** «Банковские комиссии» (проверить наличие одноимённой статьи в справочнике своей базы).
- **Тип документа:** «Платёжный ордер (списание денежных средств)».
- **Предлагаемый вид операции 1С:** «Прочее списание безналичных денежных средств».

Обычная оплата поставщику при этом остаётся исходящим платёжным поручением. Выбранный бухгалтером тип документа можно изменить вручную; повторный пересчёт автоматических предложений не должен заменять явно сохранённый ручной выбор. Старые автоматически определённые документы корректируются при восстановлении черновика или пересчёте ДДС.

Внимание: в конкретном релизе/настройке **1С:Бухгалтерия для Казахстана 3.0** для комиссии может применяться другой допустимый путь оформления, включая исходящее платёжное поручение с операцией «Прочее списание безналичных денежных средств». Сверьте форму документа и настройку учёта на **тестовой базе** до проведения. Сайт не создаёт и не проводит документ в 1С.

## Где хранятся данные

- Файл банковской выписки обрабатывается JavaScript-кодом **на устройстве пользователя**.
- Автосохранение использует `sessionStorage` браузера, а не серверную базу. Оно работает в контексте текущей вкладки и **не заменяет резервную копию**.
- **«Сохранить черновик»** создаёт локальный JSON-файл, **«Открыть черновик»** восстанавливает его.
- **«Очистить сессию»** удаляет данные рабочей области и текущий сохранённый черновик вкладки, но **не удаляет уже скачанные** JSON/Excel-файлы.
- Для чтения XLSX используется SheetJS CE **0.20.3** из официального источника; на GitHub Pages библиотека загружается с внешнего CDN. Банковская выписка в этот CDN не загружается. Для первоначальной загрузки библиотеки нужен доступ к интернету.
- Не используйте сервис на чужих или общедоступных компьютерах для конфиденциальных выписок.

## Развёртывание

### GitHub Pages

Статическая версия состоит из `index.html`, `app.js` и `workspace-core.js`. Дополнительно браузер загружает библиотеку Excel из официального CDN SheetJS. Сервер Node.js для работы этой статической версии не требуется.

### Node.js / Railway

Требуется **Node.js 20+**. При установке зависимостей нужен доступ к `cdn.sheetjs.com`.

```bash
npm install
npm test
npm start
```

Локальный адрес: `http://localhost:3000`. Проверка сервера: `GET /api/health`.

`server.js` обслуживает интерфейс и JavaScript-файлы, настраивает защитные HTTP-заголовки через Helmet. API загрузки выписок на сервере **нет**. Для стандартного запуска не требуется токен КГД.

## Структура проекта

## Что пока не реализовано

- **Прямая загрузка и проведение** платёжных поручений, ПКО/РКО или других документов в 1С.
- Подтверждённый формат обмена для **1С:Бухгалтерии для Казахстана 3.0**, включая `1CClientBankExchange` или другую выбранную обработку загрузки.
- Получение актуальных контрагентов, банковских счетов, статей ДДС и правил проведения из конкретной базы 1С.
- Поиск дублей среди **уже проведённых** документов в 1С.
- Серверная история операций, личные кабинеты, синхронизация между устройствами.
- Подключение API КГД для проверки контрагентов: такой модуль здесь пока не активен.

## Изменения классификации ДДС от 20 ноября 2026

Исправлена ошибка, когда комиссия банка ошибочно распознавалась как налоговый платёж из-за слов «НДС», «ОПВ» или «пеня» в описании комиссии. Также оплата бухгалтерских и налоговых **услуг** больше не должна попадать в категорию налогов из-за слова «налоговых».

Для выписок с колонками **«Дата выписки»**, **«Дата документа»** и **«КНП»** программа использует дату документа для операций и КНП для уточнения предложения ДДС. Для КНП 841 банковская комиссия определяется по контексту назначения; один код сам по себе не заменяет бухгалтерскую проверку.

Предложения «Алименты» и «Исполнительные документы» являются рабочими категориями для предварительной классификации. Проверьте, какие реальные статьи с соответствующими наименованиями существуют в вашей конфигурации 1С.

## Проверки и дальнейшая работа

Команда `npm test` запускает модульные проверки определения направления и суммы, ДДС, дат, дублей и базовой валидации документов. GitHub Actions запускает их при обновлении основной ветки. Эти тесты **не заменяют** проверку на реальных форматах банковских выписок и тестовой базе 1С.

Следующий этап — согласовать реальный формат обмена с используемой конфигурацией 1С, проверить на обезличенной банковской выписке, затем реализовать безопасную выгрузку с точной схемой документов и справочников.
