# STOLDOM.SITE — модуль проверки контрагентов

Первый серверный модуль для интеграции с API КГД РК:

- POST `/api/counterparty` с JSON `{"xin":"12 цифр БИН"}`;
- серверный запрос к `/services/isnaportal/public/get-sur-data`;
- токен `X-Portal-Token) хранится только в переменной окружения `KGD_API_TOKEN`;
- GET `/api/counterparty/:xin/qr` формирует QR на повторную проверку по БИН;
- GET `/api/health` показывает состояние конфигурации без раскрытия секретов.

## Railway

1. Создать Node.js service из этой ветки.
2. Установить переменные из `.env.example` в Railway Variables.
3. Вставить полученный от администратора КГД токен в `KGD_API_TOKEN`.
4. Указать фактический публичный адрес frontend в `PUBLIC_APP_URL` и `CORS_ORIGINS`.
5. Домен КГД можно изменить через `KGD_PORTAL_HOST`, не меняя код.

## Важно

- Токен нельзя помещать в HTML, JavaScript браузера, GitHub или публичные логи.
- Ответ КГД показывается с датой актуальности из `actuality`; время получения API фиксируется отдельно.
- Значения «Нет данных» не интерпретируются как отсутствие нарушения.
- Этот backend пока не создаёт 1С-файл. Совместимый формат импорта необходимо проверить на конкретной конфигурации 1С.
- Печатная форма и QR на frontend должны быть проверены после подключения публичного API-домена.
